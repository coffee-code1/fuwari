# SQL 与 NoSQL 区别

## 一、基本概念
- **SQL（关系型数据库）**：基于二维关系模型，使用标准 SQL 操作，表结构固定。
  代表：MySQL、Oracle、SQL Server、PostgreSQL
- **NoSQL（非关系型数据库）**：不遵循关系模型，结构灵活，主打高并发、海量数据。
  代表：Redis、MongoDB、HBase、Neo4j

## 二、核心区别对比
| 对比维度 | SQL（关系型数据库） | NoSQL（非关系型数据库） |
| ---- | ---- | ---- |
| 数据模型 | 二维表结构，表间通过外键关联 | 键值/文档/列族/图结构，无固定范式 |
| 表结构 | 提前定义字段与类型，修改成本高 | 动态字段，可灵活扩展 |
| 查询语言 | 标准 SQL，语法统一 | 无统一查询语言，各产品自有 API |
| 事务特性 | 完整 ACID，强数据一致性 | 多为最终一致性，事务支持较弱 |
| 扩容方式 | 纵向扩容为主，横向分库分表复杂 | 天然支持横向集群扩展 |
| 读写性能 | 高并发、大数据量表现一般 | 高并发、海量数据读写效率高 |
| 关联查询 | 支持多表联查、复杂聚合查询 | 不擅长多表关联复杂查询 |

## 三、NoSQL 四大主流分类
1. **键值型**：Redis、Memcached，适用于缓存、会话、计数器
2. **文档型**：MongoDB，适用于 APP、内容、电商业务
3. **列族型**：HBase、Cassandra，适用于大数据、日志、物联网
4. **图数据库**：Neo4j，适用于社交关系、知识图谱、路径分析

## 四、适用场景
### 适合使用 SQL
- 业务要求**事务、强数据一致性**（金融、订单、账务）
- 数据结构固定，频繁进行多表关联查询
- 传统后台系统、ERP、管理系统

### 适合使用 NoSQL
- 高并发、海量数据场景（秒杀、信息流、日志采集）
- 数据结构频繁变更
- 缓存、实时统计、分布式大数据场景

## 五、总结
- SQL：强事务、强一致，擅长**复杂关联业务**
- NoSQL：高并发、易扩展、结构灵活，擅长**海量数据场景**
- 实际项目常用**混合架构**：核心业务用 SQL，缓存/海量数据用 NoSQL
